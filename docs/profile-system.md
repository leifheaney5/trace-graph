# Profile system

Profiles are the boundary for SysML, UML, system-of-systems, Core TraceGraph, and custom vocabulary. `src/profiles.ts` is the typed registry: each profile declares its supported artifact vocabulary, relationship kinds, required and optional fields, allowed connections, validation rules, notation, default views, export mappings, description, and contextual guidance. Diagram Studio reads that registry while preserving one canonical artifact and relationship model for every profile; changing a profile changes the vocabulary and visual emphasis, not the underlying records. Custom profiles currently preserve the shared metamodel while allowing a saved display name. Future registry extensions can add typed stereotypes and richer constraints without creating an incompatible modeling engine.

Canonical relationship creation applies endpoint validation for the supported semantic subset. For example, `verified-by` requires a Requirement-to-Test connection and `allocated-to` requires a Requirement, Capability, or Mission to a Block, Part, or ConstituentSystem. Unrecognized relationship kinds remain available as explicitly retained custom semantics; invalid recognized connections are rejected with a plain-language explanation.
