# Elicitation workflow

Candidate need review supports accepted, rejected, merged, split, deferred,
duplicate, and unresolved dispositions. Non-acceptance dispositions require a
rationale, which is preserved in canonical metadata.

The sample workflow supports discovering a stakeholder, saving a canonical elicitation record, and preserving raw interview notes. Select a sentence or passage in the source textarea to extract only that exact excerpt, or use the full note when no selection is made. Source text can be extracted into a Concern, Need, Assumption, Constraint, Requirement, Decision, or ActionItem; each extracted artifact records its source and receives a `captures` provenance link from the elicitation record while the original note remains intact. Acceptance updates the latest source record and creates a candidate Need. A reviewed need can be converted into a draft Requirement through an explicit refines relationship.
